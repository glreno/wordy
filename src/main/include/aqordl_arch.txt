DRIVERS (all start with d)

1. Screen driver (ds_screendriver.h, ds_screeendriver.c, ds_screendriverA.asm)
    * To start up the screen driver:
        1. ds_disableScreen()
        2. Figure out where to put screen ram
        3. ds_initScreenRam(screen ram, len)
        4. ds_init_page(first ds_page)
        5. Build the first ds_page
        6. Load initial screen data into screen ram; ds_puts wiill work
        7. ds_init(first ds_page)
    ! ds_page:
        * union of ds_pageHeader and ds_pmData and a 4 byte ID.
        * PMBASE will be set to the start of the ds_page, so the ds_page MUST be on a 1K boundary.
    ! ds_pageHeader:
        * address and an ID number, which together are the 4 byte ID
        * screenState and queueState for communicating with the animation driver
        * Pointer to next page for the animation driver to quque up
        * nine colors
        * P/M positions and sizes
        * 156 font addresses - MSB only; note that GR.0 does AND 0xFC and GR.1 does AND 0xFE
        * Also note that this is by VCOUNT -- 2 scanlines per vcount, 4 vcount per Gr.0 row
        * the display list (up to 64 bytes)
    ! ds_pmData:
        * standard Atari player missile graphics
    ! ds_colormap
        * pcolr0-3 (player/missile colors)
        * color0-4 (playfield colors)
        * hposp0-3 (player position)
        * hposm0-3 (missile position)
        * sizep0-3 (player sizes)
        * sizem    (missile sizes)

    ! _DS_CTOR (asm, enabled via .constructor)
        ! disable callbacks on startup
        ! initialize callback vectors

    ! _DS_DLI (asm DLI handler)
        ! DLI handler
        ! update font for current screen row based on current ds_page->fonts[VCOUNT]
        ! call user defined callback (ds_setDliCallback())

    ! _DS_PAGEFLIP (asm VBI handler, enabled via .interruptor)
        ! Flip to queued up ds_page (ds_flipToPageNextVBI())
            ! Update color & PM positions & sizes
            ! Update display list
            ! Update fontlist pointer
            ! Update PMBASE to point to the ds_page's player-missile data
            ! set _DS_CURRPAGE
        ! call user defined callback (ds_setFlipCallback())
        ! start animation timer (ds_setAnimTimerCallback())
        ! clear _DS_NEXTPAGE

    ! _DS_TIMERHANDLER
        ! call animation timer callback (ds_setAnimTimerCallback())

    ! ds_initScreenRam(pointer, size)
        ! memset(pointer,0,size)
        ! Update OS screen pointers SAVMSC (start of screen RAM) and TXTMSC (start of splitscreen)

    ! ds_disableScreen()
        ! Disable the screen while the initial setup is going on.
        ! Disable interrupts too

    ! ds_init_page(page)
        ! zero out the PM data
        ! set font to E0 for all scan lines
        ! Initialize colors to default
        x Create dlist (No - you'll just overwrite it anyway)

    ! ds_init(page)
        ! Enable Player Missle Graphics
        ! Enable the DLI and point it at _DS_DLI
        ! Schedule bank to be switched in on next VBI
        ! Enable the screen, and PM, and DLI and VBI

    ! ds_setFont(page, font addr, offset in vcount, first text row, last text row)
        ! Update the fontlist to point to the specific font
        ! Do all the math so that you can just give text Y coordinates
        ! Offset param in case the first line of text isn't on a multiple of 4
        ! Start and end param are in text Y coords. Lines 2...3 will thus be:
        !   15 + 4*2 ... 15 + 4*3+3 scanlines
        ! Max VCOUNT is scan line 155 -- text line 34
        ! Min VCOUNT is scan line 0 -- text line -3
        ! Assume standard ppp display list header of 24 blank lines

    ! ds_flipToPageNextVBI(page)
        ! The page flip will occur in the VBI, and a callback will be called
        ! There is no queue. Just one pointer, and it will be set next VBI

    ! ds_flipToPageNextVBIandWait(page)
        ! The page flip will occur in the VBI, and a callback will be called
        ! There is no queue. Just one pointer, and it will be set next VBI
        ! busy-wait on DS_NEXTPAGE, return after page has been loaded

    ! ds_setFlipCallback(addr of ML routine)
        ! will be called after each page flip
        ! set to NULL or DS_NOCB to disable the callback
        ! Register A contains the new _DS_CURRPAGE
        ! Register X contains the old _DS_CURRPAGE
        * Don't use for animation and page queueing; use anim timer for that
        * Useful things to do:
            * let it be known that the old page is no longer on screen

    ! ds_setAnimTimerCallback(jiffies, addr of ML routine)
        ! Timer is number if vertical blanks
        ! callback is called by VBI when timer reaches 0
        ! Timer is restarted after the callback.
        ! set to NULL or DS_NOCB to disable the callback

    ! ds_setDliCallback(addr of ML routine)
        * Keep it short! Maybe set a timer or a flag.
        * This will be called while the next scanline is being drawn!
        ! Update DLI callback, called by _DS_DLI
        ! Disable if addr is null (set DS_DLICBV to RTS)

    ! ds_putc(char,x,y)
        ! print to the shared screen RAM
        ! assumes 40 char rows, does not check graphics mode
        ! Assumes contiguous RAM, jumps in the dlist will break this
        - might need to do this in the VBI, but maybe not - page flip callback can always call this after all
        - VBI print would be "precalculate all the write addresses generate a bunch of LDA #, STA instructions on the fly, then call THAT in the VBI"
        ! Expects internal codes; for ascii, use cputcxy()

    ! ds_put2c(right,left,x,y)
        ! print to the shared screen RAM
        ! assumes 40 char rows, does not check graphics mode
        ! Assumes contiguous RAM, jumps in the dlist will break this
        ! Expects internal codes; for ascii, use cputcxy()
        ! Note that the char params are in the wrong order! Because stack.

    ! ds_puts(x,y,len,string)
        ! print to the shared screen RAM
        ! assumes 40 char rows, does not check graphics mode
        ! Assumes contiguous RAM, jumps in the dlist will break this
        ! Expects internal codes; for ascii, use cputsxy()

    * screenState values
        * screenState 3 = ds_page is in initial state
        * screenState 2 = ds_page has been queued for the screen (animation driver has scheduled it by putting in a ds_page.next)
        * screenState 1 = ds_page is _DS_NEXTPAGE (set by ds_flipToPageNextVBI)
        * screenState 0 = ds_page is ON SCREEN (set atomically by VBI handler)
        * screenState -1 = ds_page is now OFF SCREEN (set atomically by VBI handler)
        * animation driver is expected to watch for state -1 and clean the ds_page up, deallocate fonts, etc
        * states 3 and 2 are optional; they may be set by the animation driver
    * queueState values
        * These are entirely under control of your animation driver, the screen driver never looks at them.

6. Used Letters
    - no data structure needed, just a screen address
    - Address is to 5 lines of ANTIC mode E graphics
    - Letters will be 5x5, each letter taking 6 pixels or 1.5 bytes; 26*1.5=39 bytes
    - White(bits 11): Unused
    - Grey (bits 01): Used, and not in solution
    - Green (bit 10): Used, part of solution (green OR yellow in any puzzle)
    - vu_initialize(address)
        - draw all the letters on the screen
    - vu_grey(address,letter)
        - uppercase ascii letter
        - changes the letter to grey(used)
        - no effect if letter is already grey
    - vu_green(address,letter)
        - uppercase ascii letter
        - changes the letter to green(part of a solution)
        - no effect if letter is already green
    - There is no "turn it back to unused". Call initialize again.
    - There is also no grey-to-green, so you only get one chance.

DICTIONARY BUILDER SCRIPT

    ! Reads .dict files:
        ! One word per line
        ! follow word with comma-separated list of tags
        ! Words will be sorted by the script
        ! ; comments
        ! @ commands:
            ! @DICT names a dictionary that the volume should be in
            ! @DICT with an 'x' param adds the volume to the dictionary more than once
            ! @PRIORITY indicates what order the volumes are in the dictionary
            ! @DICTD names a dictionary that a derived volume should be in
            ! @DFLAGS lists tags that indicate the word should be in the derived volume
    ! Each file becomes a Headword Volume and possibly a Derived volume
        ! Derived volume is at priority +1 after the headword volume
    ! Each volume can be in many Dictionaries, sometimes more than once
    ! Generates a single .s file for ALL dictionaries
        ! Allocates all volumes to cart banks 1-4.
        ! Generates md_volume and md_dict structures in RODATA
    Example top.dict file:
@PRIORITY 1
@DICT DICT_EA
@DICTD DICT_EA
@DFLAGS np,vc
@DICT DICT_MS,x3
about
acids,np

generates this:

    .segment "CARTBANK1"
_words_top1:
    .export _words_top1
    .byte "ABOUT", 1
    .segment "CARTBANK2"
_words_top1D:
    .export _words_top1D
    .byte "ACIDS", 2 ; 0




THE FONTS

Each tile consists of two characters, which together are an 8x8 grid.
These are generated from the standard Atari upper case letters.
Additional characters create the boundary between them.


The screen layour for a one line of a double puzzle is: (# is the both-sides tile):
0123456789012345678901234567890123456789
 [TT#OO#DD#AA#YY] XXXXX [FF#II#NN#CC#HH]

These lines are intersperced with either another line of text
OR a line or two of Mode E graphics, to top off the tiles.

The actual Atari font is actually 6x6 (except M is 7x6):

........    ........
.##..##.    .##...##
.##..##.    .###.###
..####..    .#######
..####..    .##.#.##
.##..##.    .##...##
.##..##.    .##...##
........    ........

The letters will all be black, but the backgorunds
will be available in three colors: Green, Yellow, Grey
Yellow will be the inverse of grey.
All Grey/Yellow letters will be in each font,
but only TEN of the green letters. These will be
generated when the answer to the puzzle is selected.

The codepoints in the font look a but strange, but
it's to match the internal Atari font order, which is NOT ascii.
The grey/yellow letters are in place of the real upper and lower case,
and the tile characters are [] which are right after the upper case.
so the tile for the letter T is "[Tt]"
The green letters replace the numbers, and a block of the control chars.

0x00      = SPACE
0x01-0x0F = free space
0x10-0x19 = Ten Green letters, left half (digits 0-9)
0x1A-0x1F = free space
0x20      = tile surround top+bot, atascii 64 @
0x21-0x3A = Grey letters A-Z, left half (upper case)
0x3B-0x3F = The left/both/right/top/bot tile surround , originally [ \ ] ^ _
0x40      = RIGHT blank space in the middle of a blank tile, (atascii 96 diamond ctrl-dot, ascii backquote)
0x41-0x4F = free space
0x50-0x59 = Ten Green letters, right half (Ctrl-P to Y)
0x5A-0x5F = free space
0x60      = RIGHT blank space in the middle of a blank tile (atascii \0)
0x61-0x7A = Grey letters A-Z, right half (lower case)
0x7B-0x7F = free space

To copy the static parts of a font, i.e., the grey letters and the box-drawing:
0x00
0x20-0x40
0x60-0x7A

Note that to the RIGHT HALF is equal to the LEFT HALF + 0x40
Again, these are internal codes, used for poking directly
to the screen. printf("[Tt]") will work, because CIO will map
the characters, but in ASCII to conver to lower is add 0x20 instead of 0x40.
And that doesn't work for the green letters at all. But those
need to be a lookup table anyway.

The free space for graphic characters will usually be treated as
chunks of five characters. There are 9 contiguous blocks of 5.
(two contiguous blocks of 15) and 4 more non-contiguous chars.

0x01-0x0F = free space (blocks 0,1,2)
0x1A-0x1F = free space (block 3, and one spare)
0x41-0x4F = free space (blocks 4,5,6)
0x5A-0x5F = free space (block 7 and two spares)
0x7B-0x7F = free space (block 8)

01 02 03 04 05  BLOCK 0
06 07 08 09 0A  BLOCK 1
0B 0C 0D 0E 0F  BLOCK 2

1B 1C 1D 1E 1F  BLOCK 3

41 42 43 44 45  BLOCK 4
46 47 48 49 4A  BLOCK 5
4B 4C 4D 4E 4F  BLOCK 6

5B 5C 5D 5E 5F  BLOCK 7
7B 7C 7D 7E 7F  BLOCK 8

Not in blocks of five:
1A 5A

To have 26 green characters, place them in
0x01-0x1A = green letters, left half (ATASCII 33-59, ! through ; (which includes the numbers)
0x41-0x5A = green letters, right half (ATASCII 1-27 Ctrl-A through Ctrl-Z)
Normally to write a green letter, you would do vw_writeTile(row,col,GREEN,'1')
with 0-9 being valid chars. But it will actually work with ! through :
